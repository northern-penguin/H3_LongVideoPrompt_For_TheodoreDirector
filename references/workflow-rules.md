# H3分段长视频工作流规则

## 1. 术语与交付物

- “分镜”指一次独立的H3生成段，时长必须为5—15秒。一个生成段内部可以包含多个镜头和剪切，但应控制信息负荷。
- 项目固定交付物为 `素材映射.md`、`分镜设计.md`、`H3分镜提示词.md` 和 `<项目名>.director.json`。
- 使用视频主题作为项目文件夹名。若同名文件夹已经存在，先检查内容并保留用户文件。

## 2. 创意阶段

用户没有具体想法时，先提供数个在类型、视觉语言和叙事结构上明显不同的方向。优先推荐便于拆成5—15秒段落、具有重复视觉锚点和清楚时间推进的概念。

用户选定主题后再创建文件夹。确认实际目标时长、画面风格、画幅、国家或城市、年代、季节、对白、旁白、画面文字以及结尾形态。能合理推断的次要项可先作为明确标注的暂定设计。

## 3. 素材锁定与映射

先让用户列出全部参考图片、视频和音频。参考视频的画面与伴音是两个独立角色：画面使用 `{{ref:别名}}`，只有用户明确启用其伴音时才使用 `{{ref:别名.audio}}`。

为每项素材在 `素材映射.md` 记录唯一别名、类型、用户原始称呼、本地路径、用户已确认的信息、具体用途、未见素材时的规划描述，以及身份、服装、道具、空间或声音连续性。路径允许留空。

规划描述不是对未见素材的事实识别。实际文件提供后，以真实内容修订，不让早期假设覆盖素材。

素材集在用户确认后即锁定。禁止自动新增已生成的前一分镜视频、上一分镜尾帧、已生成视频的伴音，或为方便写作而臆造的图片、视频和音频。只有用户明确添加素材后，才能更新映射和提示词；路径变化不等于新增素材。

## 4. Subject判定

`<Subject N>` 是可追踪、可复用的可见内容单元，不是源文件标签。`{{ref:别名}}` 才是素材引用。

- 有明确人物参考图的人物通常定义为Subject。
- 需要跨分镜保持身份的动物、核心物件、服装或特殊效果可按内容需要定义为Subject。
- 街道、房间、店铺等场景参考通常直接以 `{{ref:场景别名}}` 描述环境角色，不机械创建Subject。
- 仅作为首帧、尾帧或具体构图锚点的图片直接使用自定义ref引用，并说明其时间对齐角色。
- 同一项目中的复现人物保持全片稳定的Subject编号。建议按首次出现顺序建立项目级映射；某分镜未使用的编号可以缺席，不要临时重排。

正确示例：

```text
{{ref:主街道}} is the environment reference for the modern Chinese street...
<Subject 1> is the cleaner from {{ref:清洁工}}, preserving the referenced face, uniform, and tools...
```

不要把主街道机械定义为 `<Subject 1>`，也不要用 `{{ref:清洁工}}` 取代 `<Subject 1>` 后彻底删除Subject。

## 5. 分镜设计

先设计实际镜头内容，再估算自然时长，最后确定生成段数和累计时间轴。禁止先统一定成每段10秒、15秒或先定段数，再补写、拉长或压缩内容来填满时长。各段可以恰好等长，但必须分别有内容依据；也不要为了看起来不等长而刻意制造差异。

估时应考虑动作完成所需时间、对白或旁白的自然语速、表情反应与必要停顿、镜头运动和观众辨认关键信息的时间。能同时发生的动作、声音和运镜按并行节奏估算，不机械叠加。每段记录简短的“时长依据”，说明主要节拍及其用时。

只有当单个连续镜头的内容自然需要超过15秒时，才因生成时长上限把它拆成多个生成段；在自然动作节点划分，每段仍为5—15秒，不机械采用“15秒＋剩余秒数”或平均切分。若尾段不足5秒，调整相邻段的分界，使各段都能自然完成其内容。拆分组内第一段不因本次拆分标记接力，从第二段起每段都必须在标题标注 `（接续上一个分镜）`，并写明 `长镜头跨段：是（接续上一个分镜）`，表示“接力上一段”；具体记录边界前后的动作、机位和空间状态。不要为了分段插入剪切、时间跳跃或视角重置。原本包含独立镜头或剪切的内容，先按实际镜头结构划分，再分别估时；不把它们误当作同一连续镜头接力。

用户提前指定总时长时，将其作为柔性的整体叙事预算，尽量使最终总时长接近目标，允许约±10%的误差，不作为严格达标门槛。例如目标60秒，可大致安排为54—66秒。用户给出时间范围时，优先落在该范围内，边界附近允许约10%的弹性；用户另有明确的严格时长要求时，以其要求为准。通过内容取舍和自然节奏靠近目标，不为精确凑秒数而填充、拉长或压缩镜头，也不用总时长除以固定段长倒推分镜。未指定时，总时长由内容所需的各段时长精确相加得出；最终段数、时间范围和总时长均在内容与拆分确定后汇总。约10%的弹性仅适用于全片目标时长，每个H3生成段仍必须为5—15秒。

每段先取一个简洁、能识别内容的分镜名称，再记录全片时间范围、是否 `（接续上一个分镜）`、画面动作、镜头运动、声音、对白或旁白、本段实际使用的已锁定素材，以及人物、道具、光线、空间和动作连续性。

只有在两个生成段之间确实是同一未剪切长镜头的连续部分时，后一个分镜才可标注 `（接续上一个分镜）`：镜头机位/运动、时间、角色动作与空间状态必须直接连续，且边界处没有剪辑、转场、时间跳跃或视角重置。叙事有关联、人物重复出现、场景相同或动作前后相接，都不足以使用该标记。每段在分镜设计中必须写明 `长镜头跨段：是（接续上一个分镜）` 或 `长镜头跨段：否`。

若一个长镜头跨多个生成段，明确标记接续关系，但不要因此新增参考素材。对白需要按可自然说完的速度分配；被结尾截断时才使用 `<cutoff>`。

逐段核查9图、3视频、3音频上限。视频伴音仅在用户原始素材表明确启用时计入音频。

## 6.5 Theodore Director JSON 导出

完成 `H3分镜提示词.md` 后，必须运行 `scripts/export_director_plan.py "<视频项目文件夹>"`，生成 `<项目名>.director.json`。该文件对应 Theodore Director 当前 main / V7.3 的 Plan v5，可在导播台“导入”中直接载入，再点击“保存到工作流”。

- 每个素材均写入 `assets`；本地路径为空时仍保留空 `path`，以便用户导入后在导播台上传或补充 ComfyUI input 相对路径。空路径配置不可直接执行，必须向用户说明。
- 每个提示词代码块均写入一个 `shots` 项，标题、完整提示词、最终时长和顺序必须与 Markdown 一致；JSON 使用稳定 `shot_001` 式 ID。
- `latentRelay` 仅在分镜设计声明 `长镜头跨段：是（接续上一个分镜）` 时为 `true`，其他分镜均为 `false`。它是 Director 的运行时连续性配置，不改变提示词代码块必须独立生成的规则。
- 默认设置固定为 24 FPS、`h3_av_latent`、22 视频上下文帧、24 音频上下文帧、`final_output` 和 `super_resolution_second_pass`。用户可在导播台导入后自行调整。

## 6. 提示词模式选择

### 基础模式

无完整参考关系时，根据官方基础指南选择T2VA、I2VA、FL2VA或L2VA。核心字段为：

```text
integrated_multimodal_description:
overall_soundscape:
non_diegetic_music:
```

I2VA、FL2VA和L2VA需要的对齐指令仍放在第一行，但官方图片编号改为用户的 `{{ref:别名}}`。

### 完整参考模式

当素材提供人物身份、场景、动作、镜头结构、音频或编辑关系时，使用六段结构：

```text
subject_definitions:
summary:
retention_analysis:
detailed_description:
overall_soundscape:
non_diegetic_music:
```

保留 `<Subject N>`。将官方的图片、视频和音频素材编号改成用户的自定义ref格式。不要创建未登记别名。

明确的跨段长镜头在Markdown标题中写作：

```text
## 雨巷初遇｜02:12—02:24（接续上一个分镜）
```

`H3分镜提示词.md` 的标题优先直接采用对应分镜设计的名称，例如：

```text
## 雨巷初遇｜02:12—02:24（接续上一个分镜）
```

若分镜设计中有完全相同的名称，为避免提示词标题重复，只有这些重名分镜在名称后追加其组内两位序号（如 `雨巷初遇01`、`雨巷初遇02`）；不重名的分镜仍保留其设计名称。

接续关系不是 `video continuation` 或 `audio reference` 任务类型，除非用户预先提供且锁定的参考视频或音频本身确实承担官方定义的这些角色。

### 独立生成边界

`分镜设计.md` 可以记录叙事前后关系、人物或物品状态的设计连续性；这些信息只用于确定当前分镜自身应呈现的起始状态、动作和结束状态。写入 `H3分镜提示词.md` 时，每个 `text` 代码块都必须能脱离其他代码块单独提交给 H3，并且只能描述当前目标视频。

- 不在代码块中提及上一、下一或其他分镜，不写“主角在多个分镜反复出现”“承接上一分镜”“延续前一段”“为下一段铺垫”等跨段表述，也不以这些关系作为生成指令。
- 即使标题有 `（接续上一个分镜）`，该关系也只保留在标题；代码块中不得出现任何对应的接续、继承、回顾或预告措辞。
- 需要保持身份、服装、场景或物件状态时，直接在当前代码块完整描述其当前应有的状态，并仅引用已锁定的原始素材；不要引用、假定或要求 H3 读取其他分镜的生成结果。

## 7. 声音与语言

- 建立项目级稳定说话人ID，按全片首次实际发声顺序分配。
- 对白和歌词逐字保留在 `<d>[Language] ...</d>` 中；不要翻译或润色用户给出的原文。
- 画外旁白使用 `says in an off-screen voiceover`。若画面中对应人物存在，紧接着说明其嘴唇完全闭合；纯画外叙述者无需虚构一个可见人物。
- `overall_soundscape` 只总结环境声、物理动作声和非语言人声，不重复对白、歌词或非叙事配乐。
- `non_diegetic_music` 只写观众可听、角色不可听的配乐，并说明乐器、速度、节奏和动态。无配乐写 `N/A`。
- 除对白、歌词和真实画面文字外，提示词字段内容使用英文。

## 8. 审核顺序

先检查素材白名单，再检查时长和素材上限，然后检查Subject与说话人一致性、连续动作、物品状态、光线单向推进、字段顺序、英语正文和对白原文。最后运行校验脚本。脚本通过不代表创意与物理连续性自动正确，仍需人工阅读相邻分镜。
